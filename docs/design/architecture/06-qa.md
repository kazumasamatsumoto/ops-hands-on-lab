# QA 方式設計書(ラボ)

版: 1.0 / 親: [全体方式](/design/architecture/00-overall) / 対象: E2E テスト・画面比較・守りの確認・ビルド時の検査

::: tip 3 行まとめ(この文書で決めたこと)
- 主要な導線(一覧 → 詳細 → ログイン → 注文履歴)を Playwright で自動でなぞり、画面の画像も前回と比べる。
- 正常系だけでなく、「他人の注文が見えない」「攻撃の見本が 403 で止まる」も毎回確かめる。
- 重くなった画面(JS の予算超え)は、テストの前にビルドの時点で止める。
:::

## 0. 位置づけ {#s0}
全体方式の「わざと壊すスイッチ」を使い、壊したときにテストが落ちること(= テストが効いていること)まで確かめます。
配下: [D-QA-04 E2E テスト](/design/detail/D-QA-04-e2e)。

## 1. 目的と範囲 {#s1}
- **含む**: テストの種類と担当、E2E の導線、画面比較、権限と守りの確認、ビルド時の検査。
- **含まない**: 単体テスト、外部の脆弱性診断、受入テスト(現場では要る。[必要なこと一覧](/guide/checklist) 49)。

## 2. 前提 {#s2}
| 前提 | 内容 |
| --- | --- |
| 道具 | Playwright(Docker イメージ `mcr.microsoft.com/playwright` で動かす。PC に入れない) |
| 相手 | edge 経由(`http://edge:8080`)。利用者と同じ通り道を通す |
| データ | 見本の会員 `alice`(パスワード `password`)と見本の商品・注文。起動するたびに同じデータ |

## 3. 全体像 {#s3}
| 種類 | 何を確かめるか | 道具 | いつ |
| --- | --- | --- | --- |
| ビルド時の検査 | 最初に読む JS・CSS が 450kB 以下か | `ng build`(angular.json の budgets) | イメージを作るたび |
| E2E テスト | 利用者の導線が端から端まで通るか | Playwright | 変更のたび |
| 画面比較 | 見た目が前回から変わっていないか | Playwright のスクリーンショット比較 | 変更のたび |
| 権限の確認 | 他人の注文が見えないか | E2E の 1 本、または curl | 変更のたび |
| 守りの確認 | 攻撃の見本が 403 で止まり、普通の検索は通るか | [tools/attack-samples.sh](https://github.com/kazumasamatsumoto/ops-hands-on-lab/blob/main/tools/attack-samples.sh) | edge の設定を変えたとき |
| 負荷試験 | どこまで耐えるか | k6([性能方式](/design/architecture/07-performance)) | 大きな変更の前 |

## 4. 決定事項 {#s4}
### 4.1 テストの種類 {#s4-1}
| 項目 | 内容 |
| --- | --- |
| 決定 | 上の表の 6 種類を持つ。権限の確認は「正常に見える」だけでなく「**見えてはいけない物が見えない**」を必ず入れる(`bob` で `alice` の注文番号を開くと「見つかりません」) |
| 理由 | 認可の抜けは正常系のテストでは見つからない。いちばん多い事故の 1 つ |
| 却下した案 | 正常系だけ: 他人の注文が見える穴を本番に出す |
| 実物 | 確かめ方の元: [server.js の注文詳細](https://github.com/kazumasamatsumoto/ops-hands-on-lab/blob/main/apps/api/src/server.js#L190-L214) |

### 4.2 E2E テスト {#s4-2}
| 項目 | 内容 |
| --- | --- |
| 決定 | 1 本の導線: トップ → 商品一覧 → 商品詳細 → ログイン(`alice`)→ 注文履歴 → 注文の詳細。各画面で「見出し」「商品名」「価格」など利用者が頼りにする物が出ていることを確かめる |
| 理由 | 「買い物の途中で行き止まりにならない」ことを、リリースのたびに機械で確かめる |
| 却下した案 | 人が毎回手で確かめる: 忙しい日ほど省かれる |
| 実物 | [D-QA-04](/design/detail/D-QA-04-e2e)(Playwright のテストは tools/ 配下に置く) |

### 4.3 画面比較 {#s4-3}
| 項目 | 内容 |
| --- | --- |
| 決定 | 主要な画面のスクリーンショットを基準画像として保存し、毎回の画像と比べる。時刻などの毎回変わる部分は隠してから比べる |
| 理由 | CSS の 1 行でボタンが画面外に出ても、機能のテストは通ってしまう |
| 実物 | [D-QA-04](/design/detail/D-QA-04-e2e) |

### 4.4 守りの確認 {#s4-4}
| 項目 | 内容 |
| --- | --- |
| 決定 | edge の設定(WAF の閾値・例外ルール)を変えたら、攻撃の見本 6 本が 403、普通の検索 1 本が 200 になることを確かめる。送り先はラボ(`http://localhost:18080`)に固定 |
| 理由 | 誤遮断を直そうとして例外を広げすぎると、守りが外れる。直したあとで必ず両方向を確かめる |
| 実物 | [attack-samples.sh](https://github.com/kazumasamatsumoto/ops-hands-on-lab/blob/main/tools/attack-samples.sh#L22-L32) |

## 5. 目標 {#s5}
| 項目 | 目標 |
| --- | --- |
| 主要導線の E2E | 全部通る(1 つでも落ちたらリリースしない) |
| 画面比較 | 差分 0(意図した変更なら基準画像を更新し、レビューで承認する) |
| 権限の確認 | 他人の注文が見える件数 0 |
| 守りの確認 | 攻撃の見本 6/6 が 403、普通の検索 1/1 が 200 |
| JS の予算 | 450kB 以下(ビルドで強制) |

## 8. レビュー観点 {#s8}
- [ ] 主要な導線(利用者が買い物を終えるまで)が E2E に入っているか
- [ ] 「見えてはいけない物が見えない」テストがあるか
- [ ] わざと壊したとき(スイッチを入れたとき)に、テストが本当に落ちるか
- [ ] 画面比較の基準画像を更新するときの承認の流れがあるか
- [ ] 守りの設定を変えたら、攻撃の見本と普通の入力の両方を流しているか
