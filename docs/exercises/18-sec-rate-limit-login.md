# セキュリティ-2 ログインの連打を止める

::: info この演習について
- 所要時間: 約 15 分
- 使うもの: 軽量版(docker compose)。`curl`
- 関係する設計書: [セキュリティ方式 4.3 レート制限](/design/architecture/10-security#s4-3)・[D-SEC-01 WAF とレート制限 4.3](/design/detail/D-SEC-01-waf-and-rate-limit#s4-3)
:::

::: danger このラボの自分のログイン画面だけで試してください
この演習では、自分の PC の中のラボ(http://localhost:18080)に、間違ったパスワードを続けて送ります。実在するサイトや他人のサーバーで同じことをしてはいけません。
:::

## 1. この設計書はなぜ必要か

ログイン画面は、インターネットのどこからでも何度でも試せます。何も制限がないと、機械で 1 秒に何百回もパスワードを試されます。

> **よくある事故**: 会員が「password」「123456」のような弱いパスワードを使っていました。ログインの回数に制限がなかったため、機械で次々に試され、数時間で何百人分ものアカウントが乗っ取られました。登録されていたポイントが勝手に使われ、お客様への返金とお詫びの対応が続きました。

「同じ人(同じ IP)からのログインは、1 秒に何回まで」と入口で決めておけば、機械で大量に試すことができなくなります。どこで・何回まで・超えたら何を返すかを、セキュリティの方式設計書に書きます。

## 2. 何をやっているのか

サンプルストアの入口 edge(nginx)が、`/api/login` への送信を **IP ごとに 1 秒 1 回** に制限しています。人がうっかり続けて押す程度は許すため、**5 回までの「ため」(バースト)** があります。これを超えると、アプリ(api)に届く前に edge が **429 Too Many Requests** を返します。

制限はログインにだけ厳しくかけていて、商品を見るなど普通の操作は別の、ゆるい制限(IP ごとに 1 秒 20 回)です。ログインを止められている人でも、買い物の画面は見られます。

たとえ: **銀行の ATM の暗証番号** です。何度も間違えると、しばらく操作できなくなります。ただし ATM と違って、ここでは「アカウントそのものを止める」のではなく「その場所(IP)からの試行を少し待たせる」やり方です。アカウントを止める方式だと、他人が本人のアカウントをわざと止めて困らせることができてしまうためです。

## 3. まず触ってみる

1. ラボを起動します(起動済みなら不要)。

   ```bash
   docker compose up -d --build
   ```

2. まず正しいパスワードでログインできることを確かめます(`alice` / `password`)。

   ```bash
   curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:18080/api/login \
     -H 'Content-Type: application/json' -d '{"username":"alice","password":"password"}'
   ```

3. 6 秒待ってから(手順 2 で使った 1 回分の「ため」が戻るのを待ちます)、**間違ったパスワード** を 10 回続けて送ります。

   ```bash
   sleep 6
   for i in $(seq 1 10); do
     printf '%2d回目: ' $i
     curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:18080/api/login \
       -H 'Content-Type: application/json' -d '{"username":"alice","password":"wrong"}'
   done
   ```

4. 止められているあいだに、商品一覧が見られるかを確かめます。

   ```bash
   curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18080/api/products
   ```

5. 6 秒待ってから、正しいパスワードでもう一度ログインします。

   ```bash
   sleep 6
   curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:18080/api/login \
     -H 'Content-Type: application/json' -d '{"username":"alice","password":"password"}'
   ```

6. edge のログで、止めた記録を見ます。

   ```bash
   docker compose logs edge | grep "limiting requests" | tail -2
   ```

## 4. 何が見えたら成功か

手順 2: 正しいパスワードは `200` です。

手順 3: **6 回目までは `401`(パスワードが違う)、7 回目から `429`(回数が多すぎる)** になれば成功です。

```text
 1回目: 401
 2回目: 401
 3回目: 401
 4回目: 401
 5回目: 401
 6回目: 401
 7回目: 429
 8回目: 429
 9回目: 429
10回目: 429
```

6 回まで通るのは、「1 秒に 1 回」+「ため 5 回」だからです。7 回目以降は、ためが 1 秒に 1 回ずつしか戻らないので止められます。

手順 4: 商品一覧は `200` で、ログインの制限とは別に見られます。

手順 5: 少し待てば、正しいパスワードで `200` に戻ります。本人は、待てば普通に使えます。

手順 6: edge が止めた記録が残ります(IP は伏せています)。

```text
edge-1  | ... [warn] ... limiting requests, excess: 5.644 by zone "login", client: <IP>, server: _, request: "POST /api/login HTTP/1.1", host: "localhost:18080"
```

429 は edge が返しているので、api のログや `http_requests_total` には出ません。**アプリに届く前に止まっている**ことが、ここから分かります。

## 5. ここで覚える言葉

| 言葉 | 一言でいうと | たとえ | この演習で見たもの |
|---|---|---|---|
| [レート制限](/guide/glossary#rate-limit) | 決まった時間に受け付ける回数の上限 | ATM で何度も間違えると待たされる | `/api/login` は IP ごとに 1 秒 1 回 |
| バースト | 上限を少しだけ超えてもよい「ため」 | 行列の横の、少しだけ待てる椅子 | 6 回目までは通った(1 回 + ため 5 回) |
| [429](/guide/glossary#http-429) | 「回数が多すぎる」を表す応答 | 「しばらくお待ちください」の札 | 7 回目からの `429` |
| 401 | 「ログインできない(認証の失敗)」を表す応答 | 「暗証番号が違います」 | 6 回目までの `401` |
| 総当たり | パスワードを機械で次々に試すこと | 鍵を片っ端から差してみる | 1 秒に 1 回しか試せないので、数が稼げない |

## 6. 設計書ではここに書く

- **[セキュリティ方式 4.3 レート制限](/design/architecture/10-security#s4-3)**: どの入口に、どの単位(IP ごと)で、何回までの制限をかけるか。超えたら何を返すか(429)。アカウントを止める方式を選ばなかった理由(他人にわざと止められる)。
- **[D-SEC-01 WAF とレート制限 4.3](/design/detail/D-SEC-01-waf-and-rate-limit#s4-3)**: 実際の設定値(`rate=1r/s`、`burst=5`)、設定ファイルの場所、変えるときの手順。
- 一般的な設計書の番号では **D-SEC-08(アカウント乗っ取り)** に当たります。本番では、ここに「漏えいしたパスワードの使い回しの検知」や「多要素認証」なども書きます(このラボでは扱いません)。

## 7. レビューで聞く質問

- ログインの回数制限は、どこで(アプリか入口か)、何を単位に(IP か会員か)かけていますか。その数字の根拠は何ですか。
- 会社や店舗のように、たくさんの人が 1 つの IP を共有している場所から、普通の利用者が止められることはありませんか。
- 止められた利用者には、何が表示されますか。いつまで待てばよいかが分かりますか。
- アカウントを止める方式にしていないのはなぜですか。他人に本人のアカウントをわざと止められる心配はありませんか。
- 止めた記録(ログ)はどこに残り、急に増えたときに誰が気づきますか。
- パスワードの一覧を使った攻撃(少しずつ、たくさんの IP から試す)には、ほかに何で備えていますか。

## 8. 片付け

この演習では設定を変えていないので、片付けは不要です。ラボを止めるときは次のコマンドです。

```bash
docker compose down        # データも消すなら docker compose down -v
```
